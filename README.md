# Sklad.io — версія для хостингу

React + FastAPI за одним HTTPS-посиланням; PostgreSQL у Neon; Render Free.

Сайт: https://sklad-io-practice.onrender.com

Інформаційна система обліку товарів на складі. Автор: Кобзей Олександр Юрійович, ІПЗ-41. Дисципліна: Професійна практика. Викладач: Микола Пікуляк.

42 автоматичні перевірки PASS; production build і браузерні сценарії перевірено. Архітектура використовує Repository та Factory Method, атомарні операції руху товарів, ролі Admin / Storekeeper / Manager, Argon2 і JWT.

## Інтерфейс

Дизайн продовжує лабораторну 6: темна палітра з акцентами emerald, бічне меню, картки огляду та верхня панель. Розділи: Огляд, Номенклатура, Рух товарів, Звіти, Користувачі, Налаштування. Передбачено світлу/темну/системну тему, поточну дату Europe/Kyiv, повідомлення з реальних низьких залишків, компактні таблиці та мобільне меню.

Користувачі, товари, операції, профіль і зміни пароля зберігаються на сервері. Уподобання теми, щільності таблиць і прочитання сповіщень зберігаються локально у браузері. Після зміни пароля всі попередні токени перестають діяти.

Повна інструкція: DEPLOY_UA.md. Конфігурація: render.yaml. Збірка: Dockerfile. API працює під /api, документація /api/docs, перевірка стану /health.

Початковий адміністратор: admin@sklad.io. Пароль задається змінною ADMIN_PASSWORD у налаштуваннях Render. JWT_SECRET генерується Render, DATABASE_URL надає Neon. Секрети не входять у файли проєкту.

Локальні перевірки: python -m pytest tests -v. Браузером перевірені CRUD товарів, рух, пошук, фільтри, JSON-експорт, керування співробітниками, теми, сповіщення, профіль, зміна пароля, мобільне меню, права менеджера та відновлення після помилки мережі. Docker-збірка і запуск виконуються Render. Паролі й рядки підключення до БД у репозиторій не входять.

Безплатний Render засинає після 15 хвилин; перше відкриття може тривати близько хвилини. Дані в зовнішньому Neon зберігаються при перезапуску застосунку в межах тарифних квот.
